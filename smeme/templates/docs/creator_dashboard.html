Deploy, validate, list, & delete

Saving a workflow in the editor doesn't make it available to your AI — you need to Deploy it first. After deploying, use Listed to control whether it appears in your AI tool list. Use the trash icon on the dashboard to delete a workflow permanently.

{# What Deploy does #}

What Deploy does

Clicking Deploy does two things in order:

  1. 1 Runs readiness checks. A set of structural and logical checks on your saved workflow. If any check fails, deployment stops and you'll see the issues to fix.
  2. 2 Builds and saves the deployed version. Your workflow is packaged and stored as the live version your AI will use. This is what runs at evaluation time.
Deploy does not affect visibility. It only saves a new deployed version. Use Listed to control whether your AI can discover the deployed workflow.
{# Preflight checks #}

Readiness checks

These checks run automatically every time you deploy. Fix any failures before deploying.

Check What it verifies
Structure At least one question node, one conclusion node, and a single root entry point.
Reachability Every node can be reached from the root. No orphaned nodes.
Coverage Every answer option on every question node has an outgoing edge. No dead ends except conclusion nodes.
Satisfiability Every conclusion can be reached under at least one valid set of answers. No logically unreachable conclusions.
Node text All nodes have non-empty text. All question nodes have at least two answer options.

While you edit, the sidebar validation panel runs a lighter subset and shows How to fix hints under each issue.

{# Tools column #}

Deploy status: Live and Stale

The Tools column on your dashboard compares your current saved workflow with your last deployment. Your AI always evaluates against the deployed version — not unsaved or undeployed edits.

Status What it means
{{ badge("Live", "green") }} Your saved workflow matches the deployed version. Your AI is running the current version.
{{ badge("Stale", "amber") }} The graph has changed since the last deploy. Your AI is running the older version until you redeploy.
Deploy button This workflow has never been deployed. Click Deploy to publish it for the first time.

Why does my workflow show Stale?

Any change to the saved workflow after your last deploy — new nodes, removed nodes, changed edges, edited question text, or modified answer options. Stale is not an error; it means the deployed version no longer matches what you have saved.

What do I do?

Click Redeploy on that dashboard row. It updates the deployment from your current saved workflow. The badge returns to Live after a successful redeploy.

{# Listed / Hidden #}

Listed and Hidden

After a workflow is deployed, the Listed toggle controls whether it appears in the tool list your MCP-connected AI can discover.

State Visible to AI? Notes
Listed Yes Appears when your AI calls smeme_reasoning_list. You can invoke it by name.
Hidden No Deployed but hidden from your AI's tool list. Use for drafts or workflows you're not ready to surface.

Workflows are Hidden by default after deploying. Toggle Listed on the dashboard row when you're ready.

{# Download workflow #}

Downloading a workflow

Use the download icon in Actions to save the current workflow as a JSON file. This is your editor workflow — not the deployed version your AI uses. Download your workflow has the full details.

{# Usage on dashboard #}

Usage on the dashboard

The dashboard shows your plan and monthly meters: active workflows, MCP tool calls, and AI-assisted workflow builds. The MCP (mo) column lists MCP usage per workflow for the current UTC month (weighted by operation type). Meters turn amber at 80% of a cap; at 100% new workflows, AI-assisted builds, or MCP tool calls are blocked until upgrade or reset. See Plans & usage for tier limits.

{# Delete workflow #}

Deleting a workflow

On the dashboard, the trash icon in Actions permanently removes a workflow and every version in its family — deployed tools, evaluation history, and all. MCP-connected tools will no longer list or evaluate it. This cannot be undone and frees a workflow slot.

Deletion is two steps: review what will be removed, then type delete workflow permanently to confirm. In-progress workflows (still generating) have a separate Delete button with a single confirmation.

Hidden is not delete. Hidden keeps the workflow in your account and off your MCP tool list only.

To close your entire SMEme account (all workflows, billing, and profile data), use Delete your account from Profile — not the dashboard trash icon.
